2026-10-23 제한된 패치 탐색 비교: 원본 코드로 미리 만든 동일 후보 풀에서
사례당 최대 8개를 검사했다. 탐색만 사용하면 3/9, NVIDIA가 순서를 안내하면
4/9가 정해진 회귀 검사를 통과했다. 대조군은 원본 통과 게이트로 두 방식 모두
2/2 무수정 통과했다. 모델은 코드를 쓰지 않고 기존 후보 ID만 순위화했다.
9회 호출·추정 $0.111220이며 로컬 계산비와 추가 지연은 별도다. 추가 통과는
SPI FIFO B의 바이트 순서 변경이고 FIFO A까지 검증한 것은 아니다. 개발에 쓴
알려진 9개 사례, 한 사례 차이, 제한 문법이라는 범위를 명시한다. SMT 구현이나
논문 노벨티·일반 성능 우위로 표현하지 않는다. 기존 V2와는 계산 예산이 달라
공정한 동일 예산 비교로 합산하지 않는다. `docs/CONSTRAINED_REPAIR_SEARCH.md` 참조.

2026-10-23 최종 V2 비교: 실제 결함의 연구 자료 버전 9개에서 자체 검토
회귀 검사 통과 1/9, 검증 피드백 2/9. 정상 대조군 검사 통과는 각각 1/2,
2/2다. 같은 첫 응답·각 최대 2회, 실제 29회 호출·추정 $1.464060이며
추론 중 검사기·데이터는 변경되지 않았다. 이 작은 한 사례 차이는 일반적
우위를 입증하지 않는다. V1의 정상 코드 손상 해석은 TKEEP 입력 범위를 잘못
선정한 평가 오류여서 철회했다. 기록은 보존하며 수정된 V2와 합산하지 않는다.
`docs/KNOWN_BUG_BENCHMARK_V2.md`의 입력 조건·유효 신호 마스킹·오라클 한계를
따른다. 공개 게시와 실사용자 평가는 여전히 미완료다.

2026-10-23 외부 확장: `/uart`에서 다른 작성자 ZipCPU의 실제 UART CTS 결함을
재현했다. NVIDIA 요청 4회·추정 $0.174519, 네 번째 응답을 수정 없이 실행해
12개 시뮬레이션·두 제한 깊이 속성 검사를 통과했다. 첫 keep 오판, 출력 초과,
비일치 수정, 네 번째 응답의 초기 공백 파서 거부를 모두 보존했다. 파서만 고친
사후 재검사이므로 사전 고정 성공률로 집계하지 않는다. 세부 내용은
`docs/EXTERNAL_UART.md`를 따른다. 공개 게시·실사용자 평가는 여전히 미완료다.

2026-10-23 추가: `/mutation`에 정답 RTL 대조 없이 명세·Python deque·속성으로
채점하는 인위적 오류 실험을 구현했다. 주입 사례 6/6을 NVIDIA가 두 요청 이내에
수정했고, 정상 대조군은 1/2만 무수정으로 유지했다. 총 11회·추정 $0.226926.
이 새 결과는 한 authored queue의 constructed faults이며, 기존 실제 버그
9쌍 비교 결과를 대체·합산하지 않는다. [실험 설명](MUTATION_CHALLENGE.md)과
`submission/mutation-v1`의 원본 응답·검증·제출 파일을 따른다.

현재 제출 진입점은 `rtl_app.py`다. 실제 사례 3개와 12개 회귀 검사,
직접 수정·업로드 검증, 원본·후보·증거 내보내기, 9쌍 NVIDIA 비교가 구현됐다.
자체 리뷰 3/9 대 검증 피드백 2/9로 이번 비교에서는 피드백 우위가 없다.
23회 요청과 중단된 별도 개발 호출 2건을 보존했다.
[비교 기록](SEQUENTIAL_COMPARISON.md), [계약 검토](RTL_CONTRACT_AUDIT.md),
[배포 설명](DEPLOYMENT.md)을 따른다. 실제 사용자 평가는 아직 수행하지 않았다.

**RTL 개발자가 브라우저에서 실패 파형을 확인하고, NVIDIA가 제안한 수정을
독립 시뮬레이션과 제한 깊이 형식검증으로 검토하는 도구**로 고정한다.
실물 FPGA, 보드 재설정, 예약 서비스는 제출 제품의 범위에서 제외한다.
기존 비 RTL 실험과 원래 RTLRefine 결과는 원래 기록대로 보존한다.

사용자 이야기는 “리셋했는데 FIFO에서 이전 패킷이 다시 나왔다”로 시작한다.
코드, 실제 관측 파형, 수정 diff, 새 데이터 통과, 검증 범위를 한 화면에서
연결한다. 코딩 및 에이전트 엔지니어링 트랙이 목적에 맞는다.

공식 심사는 구현, 제품 경험, 구체적인 사용자 문제 해결, 아이디어의 질을
평가한다. 작은 RTL 합성 수치 하나만으로 수상을 예측하지 않는다.
공식 출처: https://nebiusglobalaihackathon.devpost.com/

### 두 번째 실제 사례: AXI TKEEP 설정

- 실제 관리자 수정: `c1c3dc0b66e98a186878b32a4d65cdcd00eaa358`, 부모
  `10b6d2f5bc50f965d6aee213415b60f1f9af58e5`를 수정 전으로 고정했다.
- 입력 TKEEP가 비활성화되면 모든 입력 바이트가 유효해야 한다. 원본은
  사용하지 않는 0 마스크를 출력에 전달해, 20바이트의 유효 데이터가 0바이트로
  관측된다. 데이터 비트 자체가 사라졌다는 주장과 구분한다.
- 독립 오라클은 8→8/16/32비트, 입력 마스크 활성/비활성, 출력 정지·재개,
  프레임 경계와 ID/DEST/USER를 확인한다. 관리자 수정본은 6회귀·4설정의
  20단계 비교를 통과한다. 이 참조는 모든 모델 프롬프트에서 제외했다.
- NVIDIA 개발 호출 5건을 보존했다. 길이 초과, 모호한 위치, 응답 토큰 초과
  2건과 부분 수정이 포함된다. 부분 수정은 4/6만 통과해 거부했다. 모델의
  성공한 수정으로 표현하지 않는다. `/keep`에서 실패와 양성 대조군을 구분한다.
- 별도로 조사한 FIFO 출력 파이프라인 후보는 세 회귀 모두 데이터 보존을
  통과했으므로 데이터 유실 사례로 채택하지 않았다. 조사 기록은 보존한다.

다음 관문은 두 사례의 개발 결과를 성능 비교로 합산하지 않고 수행한다.

1. **실제 공개 RTL 버그 최소 세 사례.** FIFO 리셋 외에 ready/valid 및
   경계 조건 사례를 추가한다. 인위적 변이와 실제 과거 버그를 구분한다.
   이번 사례는 개발용이다. 다음 사례는 프롬프트 조정에 쓰기 전에 고정한다.
2. **동일 모델·호출 상한의 비교.** 일반 코드 리뷰/시뮬레이션 피드백과
   반례·형식검증 피드백을 같은 문제에서 비교한다. 실제 호출 수, 토큰,
   비용, 검증 결과, 잘못된 수정의 수용 여부를 모두 기록한다.
   현재는 성능 우위가 입증되지 않았다.
3. **안 좋은 수정을 확실히 거부.** 출력-valid를 묶어 오류를 숨기는 수정이
   새 데이터 회귀 검사에서 실패하는 예를 포함한다. 타임아웃을 통과로
   바꾸지 않는다. Yosys는 SAT 타임아웃에도 종료 코드 0을 낼 수 있어
   명시적 결과를 검사한다.
4. **독립 RTL 사용자 평가.** 동의한 설계자에게 반례 이해, 자신의 지원 범위
   수정 검사, 결과·증거 내보내기를 수행하게 한다. 실제 발언과 작업 시간을
   기록한다. 사용자 연구나 절감 시간을 만들어 쓰지 않는다.
5. **제출 경험 완성.** 공개 저장소·라이선스·재현 설명·안정된 Web 데모·3분
   이내 영상을 일치시킨다. 공개 게시와 계정 작업은 별도 단계다.

유사 연구가 있으므로 최초 자동 RTL 디버거라고 주장하지 않는다.
NVIDIA FVDebug: https://arxiv.org/html/2510.15906
현재 강점은 실행 가능한 증거와 실패 처리이며, 알고리즘 신규성이나 논문
가능성은 별도의 선행 연구 및 비교 결과로 판단해야 한다.

## 역할과 범위

제출 준비 파일은 `submission/rtlrefine-final`에 모았다. 공개 저장소·호스팅·
YouTube·Devpost 게시 상태는 준비 완료와 구분한다. 사용자의 계정/게시 목적지가
연결되지 않은 상태에서 공개됐다고 표현하지 않는다.

에이전트가 구현·실험·UI·재현 패키지를 맡는다. 사용자의 RTL 역량은 속성의
의미와 환경 가정이 맞는지 검토하고 실제 개발 작업을 평가하는 데 쓰는 것이
가치가 크다. 실물 보드는 필요하지 않다.

현재 Web 진입점은 `/`, 실제 FIFO 사례는 `/reset`이다. 기존 산술 RTL 검토는
`/review`, NVDLA 결과는 `/external`, 원래 실험은 `/lab`에 남겼다.
