# 기능 완성본을 제출에 반영하기

1. `video/RTLRefine-functional-demo.mp4`를 YouTube에 새로 올리고 공개(Public)로
   설정합니다. 제목과 설명은 `YOUTUBE.md`를 사용합니다.
2. Devpost의 Video URL을 새 주소로 바꿉니다. 기존 영상은 추가 링크로 남길 수
   있습니다. 현재 영상은 실제 기록된 NVIDIA 수리임을 표시하고, 회귀 검사는
   화면에서 새로 실행합니다. 녹화 중 추가 추론은 없습니다.
3. About을 `DEVPOST_ABOUT.md`로 갱신합니다. 개인 참가 기준 I를 사용했고,
   실패한 모델 요청과 검증 한계도 남겼습니다. 이름은 동일하며 새 피치와
   v1.4.0 테스트 빌드 링크는 `PROJECT_FIELDS.md`에서 복사합니다.
4. `screenshots/`에서 정확한 수정과 회귀 실행 결과가 보이는 이미지를 갤러리에
   올립니다. 제목용 `cover.png`는 실제 실행 화면이 아닌 별도 그래픽입니다.
5. 도구 피드백을 갱신하고 최종 제출 상태를 확인합니다.

이번 실증은 직접 구성한 FIFO 결함과 정상 대조군을 사용합니다. 새로운 실제
버그 발견이나 범용 수리 성공률로 표현하지 않습니다. 회귀 검사 191개는
두 입력 시퀀스의 assertion 수이며, 서로 다른 프로젝트 191개라는 뜻이 아닙니다.
